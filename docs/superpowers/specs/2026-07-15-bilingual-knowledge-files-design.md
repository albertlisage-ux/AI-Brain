# 双语知识文件规范设计

## 中文

### 目标

让 AI-Brain 以后由维护者或 AI 新建、保存或实质重写的知识文档同时提供中文与英文，并保持 Obsidian 链接、属性和代码示例简洁稳定。

### 适用范围

双语规则适用于人工编写的 Markdown 知识文件，包括笔记、MOC、Prompt、Daily、设计说明、实施计划和维护文档。新文件从创建时即采用双语结构；实质重写现有文件时，将整个文件整理为双语版本。

下列内容不要求翻译：源代码、JSON/YAML 等机器配置、数据库、缓存、模型文件、二进制文件、第三方内容、工具生成物和逐字翻译后会失真的命令输出。

### 文件结构

1. YAML frontmatter 保留一份，字段名和枚举值使用稳定的英文标识；`aliases` 可以同时包含中英文名称。
2. 主标题可以使用“中文标题 / English Title”，正文先放完整中文区，再放完整英文区。
3. 两个语言区表达等价信息，但允许为自然表达调整句式，不要求逐字翻译。
4. WikiLink、Markdown 链接、文件路径和属性值保持一致，不为英文内容创建重复笔记或重复图谱节点。
5. 代码块、命令、配置和结构化示例只保留一份；通过中英文说明共享，不复制代码。
6. 文件名继续遵循现有命名规则，优先使用英文 kebab-case，不因双语正文创建两个文件。

### 持久规则

在仓库根目录创建 `AGENTS.md`，记录以上适用范围、排版方式和例外。该文件本身采用完整中文区与完整英文区，供以后参与维护的 Codex 或其他代理自动读取。

### 当前改动

将 `04 Prompts/obsidian-knowledge-graph-optimization.md` 改为完整双语 Prompt：保留中文版本并增加语义等价、可独立复制使用的英文版本。同步增加“双语输出”要求，确保该 Prompt 以后生成的知识文件也遵守本规范。

### 验收标准

- 根目录存在中英双语 `AGENTS.md`，且明确范围、结构和例外。
- 图谱优化 Prompt 包含完整的中文与英文用途、Prompt 和使用说明。
- 中文 Prompt 和英文 Prompt 都明确要求人工知识文档采用双语结构。
- YAML frontmatter 可解析，Markdown 代码围栏成对，`git diff --check` 通过。
- 当前未提交的 Neon Observatory 设计与计划改动保持不被覆盖。

# Bilingual Knowledge File Standard Design

## English

### Goal

Ensure that knowledge documents newly created, saved, or substantially rewritten by maintainers or AI in AI-Brain provide both Chinese and English while keeping Obsidian links, properties, and code examples concise and stable.

### Scope

The bilingual rule applies to human-authored Markdown knowledge files, including notes, MOCs, prompts, daily notes, design specifications, implementation plans, and maintenance documentation. New files use the bilingual structure from creation; when an existing file is substantially rewritten, the entire file is reorganized into a bilingual version.

The following do not require translation: source code, machine configurations such as JSON or YAML, databases, caches, model files, binary files, third-party content, tool-generated artifacts, and command output that would lose accuracy if translated literally.

### File Structure

1. Keep a single YAML frontmatter block. Field names and enum values use stable English identifiers; `aliases` may include both Chinese and English names.
2. The main title may use “中文标题 / English Title.” Place a complete Chinese section before a complete English section.
3. The two language sections convey equivalent information, but wording may be adapted for natural expression rather than translated word for word.
4. Keep WikiLinks, Markdown links, file paths, and property values consistent. Do not create duplicate notes or graph nodes for English content.
5. Keep code blocks, commands, configuration, and structured examples only once. Share them through bilingual explanations instead of duplicating code.
6. Continue following the existing file-naming rules, preferably English kebab-case. Do not create two files solely to separate the languages.

### Persistent Rule

Create `AGENTS.md` at the repository root to record the scope, layout, and exceptions above. The file itself uses complete Chinese and English sections so that Codex and other agents maintaining the repository can read it automatically in future sessions.

### Current Changes

Convert `04 Prompts/obsidian-knowledge-graph-optimization.md` into a complete bilingual prompt: preserve the Chinese version and add a semantically equivalent English version that can be copied and used independently. Add a bilingual-output requirement so knowledge files generated by the prompt also follow this standard.

### Acceptance Criteria

- A bilingual `AGENTS.md` exists at the repository root and clearly defines scope, structure, and exceptions.
- The graph-optimization prompt contains complete Chinese and English purpose, prompt, and usage sections.
- Both the Chinese and English prompts explicitly require human-authored knowledge documents to use a bilingual structure.
- YAML frontmatter parses, Markdown code fences are balanced, and `git diff --check` passes.
- The existing uncommitted Neon Observatory design and plan changes remain untouched.
